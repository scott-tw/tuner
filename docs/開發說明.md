# 調音器 開發說明

給之後維護、修改程式的人看（包含用 Claude Code 修改時）。完整需求規格見 [SPEC.md](SPEC.md)。

---

## 一、技術原則

- **原生 HTML／CSS／JavaScript**：不用框架、**不需要建置（build）**，檔案改完直接就是網站。
- **不使用 npm 套件**：自動測試只用 Node 內建的 `node --test`。
- **無後端**：不上傳任何聲音或個人資料，所有分析在手機上完成。
- **託管在 GitHub Pages**：推上 GitHub 就自動部署。
- **PWA**：可安裝到主畫面、可離線使用。

## 三、在電腦上執行與預覽

在「調音器」資料夾開終端機，執行：

```bash
python3 -m http.server 8000
```

再用瀏覽器開 http://localhost:8000。localhost 可以使用麥克風，不需要 https。

> 注意：App 有離線快取，本機預覽時如果看到的是舊畫面，請在瀏覽器開發者工具「Application → Service Workers」按 Unregister，或用無痕視窗開啟。

## 四、自動測試

```bash
node --test
```

會自動執行 `tests/` 裡的所有測試檔，約 20 秒跑完。目前 21 項，全部通過才可以 commit。每次修改偵測引擎都要跑。

（Node 25 起，`node --test tests/` 這種寫法會把資料夾當成檔案而失敗，所以不要加參數。）

測試內容：

| 測試 | 標準 |
|---|---|
| 純音 41–2093 Hz，A4 = 438／440／442 | 誤差 ≤ 2 音分 |
| 含泛音（第二泛音比基頻強） | 誤差 ≤ 2 音分、八度正確 |
| 顫音（±30 音分、5.5 Hz） | 誤差 ≤ 10 音分 |
| 白雜訊、靜音 | 不回報音高 |
| 音高加雜訊 | 誤差 ≤ 5 音分（低音區放寬） |
| 弱基頻男聲 D2–C4、童聲 E3–C6 | 八度正確率 ≥ 99%（實測 100%） |
| 連續性檢查（八度防護第 2 層） | 零星的八度誤判全部拉回 |
| 五線譜各譜號的音符位置 | 位置正確 |

### 用真實聲音測準確度

用另一台裝置開測試音產生器 https://scott-tw.github.io/tuner/tools/test-tone.html，播放指定的音（純音、含泛音或模擬男聲），再用手機的調音器聽，看顯示是否正確。

## 五、部署（發布新版）

程式改好、測試通過後，先把 `js/app.js` 的 `APP_VERSION` 改成當天日期（例如 `2026.09.29`），再執行：

```bash
git add -A
git commit -m "說明這次改了什麼"
git push
```

推上 GitHub 後約 1 分鐘，GitHub Pages 會自動更新網站：

- 網站：https://scott-tw.github.io/tuner/
- 程式碼：https://github.com/scott-tw/tuner

使用者**不需要重新安裝**：

- App 打開時會在背景檢查新版。下載到新版後，首頁會出現「🎉 有新版本，點這裡更新」，點一下就換成新版。沒點的話，下次打開也會是新版。
- 設定頁最下方會顯示版本號，可以確認手機上跑的是哪一版。

### ⚠️ 新增檔案時的注意事項

`sw.js` 裡有一份「要存到手機上的檔案清單」（`FILES`）：

- **只修改既有檔案**：不用動 `sw.js`。
- **新增檔案**（新的 JS、CSS、圖示、頁面等）：要把它加進 `FILES`，並把 `CACHE` 的版本號加一（例如 `tuner-v1` → `tuner-v2`），否則離線時用不到新檔案。

這條規則也寫在 CLAUDE.md，Claude Code 修改時會自動遵守。

## 六、偵測引擎重點（js/pitch.js）

- **演算法**：YIN（差異函數、累積平均正規化、絕對門檻 0.15、拋物線內插），再以「多個週期一起量」提高高音的精準度。
- **取樣率**：一律從 AudioContext 取得，不寫死 44100 或 48000。
- **各模式參數**：

| 模式 | 偵測範圍 | 每秒分析 | 平滑 | 「準」的範圍 |
|---|---|---|---|---|
| 樂器 | 40–2100 Hz | 約 25 次 | 最近 7 格取中位數＋指針緩動 | ±5 音分 |
| 童聲／女聲 | 150–1200 Hz | 約 30 次 | 最近 5 格取中位數 | ±15 音分 |
| 男聲 | 60–600 Hz | 約 30 次 | 最近 5 格取中位數 | ±15 音分 |

- **八度防護三層**（人聲模式）：
  1. 依聲音類型限定偵測範圍。
  2. 連續性檢查：跳了剛好一個八度，要持續 120 毫秒才採信（`createOctaveGuard`）。
  3. 次諧波驗證：兩倍週期處有明顯更深的谷，就改用低八度。

## 七、平台限制（iOS Safari 等）

- **啟動音訊與麥克風**：必須在使用者點擊按鈕的那一下直接啟動，這是 iOS 的限制。
- **切到背景再回來**：手機可能暫停音訊，App 會顯示「點一下繼續」。
- **螢幕保持亮著**：用 Screen Wake Lock，不支援的瀏覽器會自動略過。
- **iPhone 播放音量**：開著麥克風時，播放的音量有時會變小，這是系統限制。
- **收不到聲音的保護機制**（`js/app.js` 的 `checkSilence`、`js/audio.js` 的 `startAudio`）：
  - 麥克風連續 2.5 秒送出「完全無聲」（連雜音都沒有），代表聲音沒進來。App 會先自動改用手機一般的收音方式（`getUserMedia({ audio: true })`，含降噪）重試一次；仍然無聲才顯示說明。
  - 已允許權限卻 5 秒沒有回應，視為啟動失敗並顯示說明。
  - 這是因應某些 Android 手機「網頁版正常、安裝成 App 後收不到聲音」的情況。
- **三星瀏覽器安裝的 App**：曾出現「三星瀏覽器正在使用麥克風」，但畫面沒有反應的情況；用 Chrome 安裝則正常。研判是舊版程式還留在快取裡，舊版收不到聲音時不會顯示任何說明。若再發生，請先確認設定頁的版本號，再用「麥克風檢查」截圖。
- **iPhone／iPad（Safari 加入主畫面）**：尚未實機測試。iOS 16.4 以後，主畫面上的網頁 App 可以使用麥克風，但 iOS 可能每次打開 App 都會重新詢問麥克風權限（這是 iOS 的做法，不是錯誤）。
- **麥克風檢查**（設定頁）：顯示使用方式（網頁／App）、瀏覽器、權限、音訊引擎、麥克風狀態、收音方式、取樣率和即時音量，方便使用者截圖回報問題。

## 八、用 Claude Code 修改的方式

1. 在「調音器」資料夾開啟 Claude Code，它會先讀 CLAUDE.md 的開發規則。
2. 描述問題時越具體越好，例如：

   > 在 Galaxy Tab 人聲模式選男聲，唱 A2 時畫面有時跳成 A3，大約每 3 秒跳一次。請檢查八度防護的連續性判斷，修正後重新執行測試。

3. 修改完成後，Claude Code 會跑測試、commit，並依指示推上 GitHub。
